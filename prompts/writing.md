# 精读与导读写作规则

适用于 ⭐ 精读卡片（标题 `title_zh`、正文 `analysis`）和今日导读（`guide`）。

## 读者

读者是懂这个领域的工程师或研究者，但**没有读过这篇论文**，也不打算读。他们知道 VLM、CoT、LoRA、RL 是什么，不知道这篇论文自己定义的记号、数据集代号和实验名称。

写完后用这个标准检查每一句：一个没读过论文的同行，只读到这一句为止，能不能看懂它在说什么、为什么要说它。看不懂的句子，要么补上缺的前提，要么删掉。

精读必须在读完 PDF 全文后再写。摘要可以当作叙述的骨架（作者通常已经把「现象 → 解释 → 证据」排好了），全文用来补上摘要里没有的东西：具体的实验是怎么做的、一个能让人看懂的例子、数字的确切含义、作者自己承认的局限和你发现的问题。

## 精读卡片

### 标题

一句话写出论文最重要的发现，让没读过论文的人看得懂。不直译论文原标题，不超过 35 个字（英文单词、数字各按 1 个字计）。

数字只有在不需要解释就能看懂时才放进标题。「RL 让搜索 Agent 涨了 30 个点」可以；「换图只改 3 个点」不行，因为读者不知道换的是什么图、3 个点相对于多少。拿不准就不放数字，把数字留给正文。

### 讲述顺序

按正常人给同事讲一篇论文的顺序写：

1. **问题**。这篇论文面对的是什么现象或困难，为什么它是个问题。一两句就够，但不能省。如果现象本身反常，要把反常之处说完整：不能只写「而图像一直在上下文里」，要写「图像一直在上下文里，模型有足够的信息来判断」。然后说论文的答案是什么。
2. **证据或做法**。论文怎么证明这个答案，或者方法具体怎么做。把关键实验的操作讲清楚，让读者能自己判断这个证据硬不硬：对什么做了什么，如果假设成立应该看到什么，实际看到了什么。
3. **进一步的发现**。在主要结论之上，还有什么值得知道的：原因分析、例外、哪些情况下不成立、怎么修。
4. **保留意见**。具体指出缺了什么或哪里要打折扣：模型规模、数据范围、缺少的 baseline、没测的场景、对比里的混淆因素。作者自己承认的局限也算。每条说明它会影响哪个结论。
5. **对读者的含义**。对做什么工作的人、有什么实际影响、可以怎么用。不做总结。

不写空话式的铺垫（「随着大模型的快速发展」），也不写任何论文都适用的句子（「这篇论文追问其原因」「作者做了大量实验」）。第一句直接进入这篇论文特有的问题。

### 句子之间要有逻辑

每一句要接得上前一句。常见的衔接是：上一段留下一个问题，这一段回答它（「既然答案跟着文字走，问题就变成写下的关系为什么会错」）；先说预期，再说实际结果；先说结论，再说它依赖的条件。

把并列的事实一条条摆出来，不是精读。如果两句话调换顺序也不影响阅读，说明它们之间缺少关系，要么补上「因为、所以、但是、也就是说」背后的那层意思，要么删掉其中不重要的一句。

### 术语、记号和数字

- 论文自己定义的记号和缩写（某个变量名、某种条件的代号、数据集内部的子集名）一律不用，改成直接描述它指什么。只有它在正文里还会反复出现、或者它本身就是论文的贡献（方法名、基准名）时才保留名字，并在第一次出现时用白话讲清楚。
- 每个数字第一次出现时，要让读者知道它量的是什么、和什么比。「图像效应 69.6」看不懂；「答案随图变化的幅度平均是 69.6 个点（100 表示完全跟着图走，0 表示完全不看图）」看得懂。指标是论文自己定义的，就顺带说明它的取值范围和方向。
- 数字只留支撑论点的那几个。同一个论点有多个数据集、多个模型的结果时，挑最有代表性的一个，或者给范围。
- 引用数字前回到原文的表格或正文核对：它属于哪个模型、哪个数据集、哪个实验组。不同实验组的数字不能拼在一句里当成同一组的结果。
- 能举例就举例，例子必须来自论文（图里的样例、正文里的案例），不要自己编。

### 篇幅

- **头条**（本期 ⭐ 里主题分数最高的一篇，页面把它排在最前；`in.json` 里 `headline: true`）：1,000–1,300 字，5–6 段。完整展开主要发现、支撑它的实验、进一步的发现、保留意见和含义。
- **其他 ⭐**：600–800 字，3–4 段。只讲一个核心发现和支撑它的那一个实验，加上保留意见和含义。次要发现压成一句或者不写。

篇幅不够时，删掉次要的发现，不删解释。把很多发现压进很少的字里，结果一定是读不懂。动笔前先想好这篇最重要的是哪一件事，篇幅优先给它。

字数的算法：汉字和中文标点各算 1 个字，一个英文单词或一个数字算 1 个字，行内标记的符号不算。

### 其他

- 方法用论文里的原词讲清楚，不评价方法本身，不写「方法很朴素」「思路清晰」这类话。
- **论文里没有、由你自己推出来的判断，必须用第一人称标明**（「我怀疑」「我觉得」「按表里的数字算」），并说出依据。读者要能分清哪些是论文的结论、哪些是写稿人的看法。反过来，论文里有的内容不要加「我觉得」。
- 信息缺失时不写，不用占位文字。

## 行内标记

| 写法 | 用途 | 数量 |
|---|---|---|
| `==概念==` | 读者必须理解的核心概念、论文提出的方法名 | 每段 ≤ 2 |
| `**内容**` | 最重要的结论、风险、需要特别注意的地方 | 每段 ≤ 1 |
| `[[glossary-id]]` 或 `[[glossary-id\|显示文字]]` | 术语表里的词，鼠标悬停显示解释 | 新术语先加进 `site/data/glossary.json` |
| `[[@论文ID\|显示文字]]` | 链接到本期另一篇论文（导读里用） | — |

## 配图（`figures`）

图片直接引用论文 arXiv HTML 版（`https://arxiv.org/html/<id>v<n>`）里的图片文件，不下载、不转存。图片有两种写法，都要找：`<img src="….png">`，以及矢量图 `<object type="image/svg+xml" data="….svg">`（SVG 可以直接当图片用）。地址按相对路径拼成 `https://arxiv.org/html/<相对路径>`，写之前用 curl 确认返回 200。直接画在页面里的图（`<svg id="S3.F1.pic1" class="ltx_picture">`，通常是 TikZ）没有单独的文件：这类图写成 `{"src": "https://arxiv.org/html/<id>v<n>", "svg_id": "S3.F1.pic1", …}`，页面打开时会从 arXiv 取回这张 SVG 显示。没有 HTML 版本、或里面没有可用图片的论文就不配图。

- 每张图的字段：`{"src", "ref"（原文图号，如 "Figure 3"）, "caption_zh", "after"（可选）, "layout"（可选：full / side）}`。
- **正文配图 1–2 张**，写 `after: n`，表示放在第 n 段之后。图要和它前面那段文字直接相关：方法段配方法图，结果段配结果图。
- **其余值得看的图**不写 `after`，作为卡片底部的缩略图，点开是轮播。头条显示全部缩略图；其他 ⭐ 卡片默认显示前 3 张，其余收在 more 按钮里。所以把最重要的排在前面。
- **图注自己写**：一两句中文，说清楚"这张图在看什么、该看哪里"，不逐句翻译原文图注。可以补上正文里的关键数字，可以用 `==概念==`、`**重点**` 和术语标记。
- 宽图会占满一栏；接近方形的图（宽高比 < 1.4）会自动浮在右侧、正文绕排，一般不用写 `layout`。

## 今日导读

导读是一篇 2–3 段、约 600 字的短文，让读者在一分钟内知道这一期有什么、先看哪篇。按正常文章的方式写。

- **按话题组织**，不按 ⭐ / 非 ⭐ 分段。先通读本期全部论文，看有没有几篇在讲同一件事、或者结论可以互相对照；有就把它们放在一起讲，并用一句话点出它们的共同点。找不到贯穿的线时，按方向分段（比如模型、评测、应用），不要硬凑主题。
- **⭐ 论文必须全部提到**；非 ⭐ 论文挑 3–5 篇值得一看的，只写本期 `shown` 里的论文。页面会自动在 ⭐ 论文的链接前加 ★，不用手写。
- 当天没有 ⭐ 时照常按话题写。
- **每篇先说它解决什么问题或发现了什么，再给最关键的数字**。读者没读过这些论文，只有名字和数字是看不懂的。数字要让人知道量的是什么：论文自己定义的指标可以用，但要顺带解释；解释不清就换一个不用解释的数字。方法名和术语同理，第一次出现时用半句话说明它是什么。⭐ 论文不要照抄精读卡片的标题，可以说读它时要注意什么。
- **论文名用 `[[@id|名字]]` 放在句子里自然的位置**，不要求放在句首，也不要每句都以论文名开头。显示文字优先用论文自己的短名（方法名、基准名，或标题冒号前的部分）；实在没有名字的论文才用描述代替（`[[@id|一项关于视觉 token 保留的研究]]`）。
- 可以有承上启下的句子，但它必须有内容（「同样的怀疑也落在评测分数上」）。不写没有信息的引导句（「本期亮点如下」「下面几篇值得关注」）。
- 论文之间的关联如果是你自己的判断，而不是论文互相引用，用「可以对照着读」这类说法，不要写成它们互相印证。

## 禁用表达

值得注意的是、综上所述、总而言之、不难看出、具有重要意义、为……奠定了基础、开辟了新的方向、令人振奋、显著提升（后面没有数字）、未来值得进一步探索、三连排比（「高效、灵活且可扩展」）、堆叠的模糊措辞（「可能在一定程度上」「或许有助于」）。

## 术语表（`site/data/glossary.json`）

收录有意思的词，或者不懂就看不下去的词。每个词全局只写一次，以后各期直接复用。解释写 1–3 句，用大白话说清楚它是什么、在这里有什么用。
